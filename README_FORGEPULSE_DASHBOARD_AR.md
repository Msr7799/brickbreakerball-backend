# ForgePulse MCP 2.0 · دليل التحديث والتشغيل

## شنو الجديد؟

هذه **نسخة معدّلة من المشروع الموحّد الأصلي** وليست سيرفر مستقل:

- `/mcp-dashboard` داشبورد RTL جديد بستايل كريم وزيتوني وفحمي، مستوحى من المرجع.
- `/dashboard.html` لوحة Google Play Billing الأصلية ما انحذفت. تغيّرت ألوانها بعيداً عن الكحلي.
- `/api/mcp` أدوات MCP الخمس عشرة الموجودة سابقاً، الآن مع تسجيل لكل تنفيذ ناجح/فاشل في MongoDB.
- `/api/mcp-control/overview` يعرض خدمات وأدوات وإحصائيات **فعلية** (يتطلب تسجيل دخول المسؤول).
- `/api/mcp-control/check` يتحقق من الخدمة المطلوبة باستدعاء حقيقي (POST، يتطلب جلسة وأصل طلب مطابقاً).
- `/api/mcp-control/run` يشغّل أدوات قراءة آمنة من داخل الواجهة مع Validation وسجل تدقيق.
- `/api/mcp-control/activity` سجل آخر 80 عملية دون حفظ كلمات المرور أو مخرجات API الحساسة.
- اللون: خلفية عاجية، بطاقات بيضاء، تدرجات زيتونية، شريط جانبي فحمي، بدون كحلي.
- واجهة مناسبة للكمبيوتر والجوال.

## الأهم: لا تخلط بين ثلاث حالات

1. **غير مهيأ:** متغيرات البيئة غير موجودة، ولا نعتبر الخدمة متصلة.
2. **لم يُفحص:** القيم الأساسية موجودة، لكن ما وصلنا رد ناجح من API.
3. **متصل:** اختبار اتصال فعلي ناجح خلال آخر 30 دقيقة.
4. **فشل الفحص:** API أرجع خطأ أو صلاحيات ناقصة، والتفاصيل تظهر بالواجهة.

`Google Play RTDN` يعتبر الاتصال ناجحاً عندما يوجد إشعار **اختبار** محفوظ في MongoDB. هذا لا يثبت صحة شراء حقيقي.
`Vercel Runtime` يعني إن سيرفر Next.js استجاب فقط، وليس اختبار حساب Vercel API.
نتيجة Firebase تفحص قراءة المسار المحدد في `FIREBASE_ALLOWED_PREFIX` حتى لو المسار فارغ.

## تشغيل ونشر

1. احتفظ بنسخة احتياطية من الريبو الحالي، ولا تمس ملف `.env.local` أو أسرارك.
2. فك ZIP وانسخ الملفات إلى الريبو الحالي `brickbreakerball-backend` بعد مراجعة التغييرات في Git.
3. داخل جذر المشروع نفذ:

```powershell
npm install
npm run check
npm run build
```

4. ارفع الكود فقط إلى GitHub. **لا ترفع `.env.local` ولا ملفات مفاتيح JSON ولا `node_modules`.**
5. من Vercel تأكد إن اسم قاعدة MongoDB هو `brickbreakerball` وإن متغيرات البيئة القديمة ما تغيرت؛ لا تحتاج إلى أسرار جديدة لهذه الواجهة.
6. Redeploy إلى Production. افتح:

```
https://brickbreakerball-backend.vercel.app/mcp-dashboard
```

7. سجل بنفس `ADMIN_PASSWORD` الموجود مسبقاً في لوحة المشتريات.
8. اضغط فحص خدمة مثل MongoDB ثم Firebase. شوف الحالة، وبعدها شغّل أداة قراءة مثل `gateway_status` أو `firebase_read`.
9. انتقل إلى **سجل النشاط** وتأكد إن الفحص والتشغيل يظهران مع النتيجة والمدة.

## المهم عن الصلاحيات

- حساب Firebase Operator اللي جهزته يملك صلاحيات IAM إدارية واسعة، لكن **أدوات هذا الإصدار للقراءة فقط**. هذا مقصود عشان ما نصير نعدل بيانات الإنتاج عن طريق واجهة بدون تدفق تأكيد وتراجع وإدارة أذونات.
- `FIREBASE_ALLOWED_PREFIX=/mcp` ما يسمح للـ MCP بقراءة `/adminEditor` من خلال أداة `firebase_read`. لا تغيّر قيمة المسار إلى `/` إلا بعد مراجعة متطلبات الخصوصية والحماية.
- تتبع اتصال Firebase يعتمد `FIREBASE_SERVICE_ACCOUNT_JSON` و `FIREBASE_DATABASE_URL`.
- AdMob وAdSense يحتاجان OAuth Refresh Tokens صالحة. وجود متغير فارغ أو placeholder ما يكفي.
- الأدوات اللي تحتاج Account ID تستخدِم الصيغة `accounts/pub-...`، ولا تحفظ البيانات المسترجعة في سجل العمليات.
- عمليات OAuth وتقارير Google قد تستهلك حصة الـ API؛ استخدم زر الفحص باعتدال.

## الأمان

- كل APIs الإدارية تعتمد على Cookie جلسة لوحة المشتريات نفسها مع حماية Origin للطلبات POST، و`Cache-Control: no-store`.
- `MCP_BEARER_TOKEN` يبقى سراً على السيرفر ولا يظهر في الصفحة.
- بيانات اعتماد Firebase/Google تبقى في Vercel فقط.
- سجل `mcp_audit` يسجل: وقت، خدمة، اسم أداة، نجاح/فشل، زمن تنفيذ، ورسالة مختصرة. لا يخزن معاملات أدوات MCP أو نتائجها.
- لا تنشر الداشبورد للعامة، وراجع إعدادات Vercel ونطاقات الثقة.

## ملاحظة عن الاختبارات

تم فحص ملفات TypeScript/TSX لغوياً وإجراء اختبارات منطق الإشعارات وملفات JavaScript. لم يتم الاتصال بحساباتك الحقيقية أو تشغيل `next build` في بيئة إنتاجك. **لا تعتبر أرقام الداشبورد حقيقية قبل النشر واختبار الاتصال من حسابك.**

## المشاكل الشائعة

- `401 Unauthorized` = سجل دخول من نفس الموقع.
- `403 Invalid origin` = احرص إنك تتصفح رابط Vercel نفسه بدون proxy غير مضبوط.
- `Database unavailable` = راجع متغيرات MongoDB.
- `Not configured` على AdMob أو AdSense = أكمل OAuth من السكربت الأصلي بالدليل.
- نتيجة Firebase فارغة = طبيعي إذا `/mcp` مو موجود، طالما الفحص نفسه ناجح.
- `Google API HTTP 403` = بيانات الاعتماد موجودة لكن الصلاحيات/الـ API غير كافية.
